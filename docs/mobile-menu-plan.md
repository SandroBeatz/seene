# Раздел «Меню» в мобильном приложении: план

Статус: **идёт работа, фазы 0–1 собраны** · 2026-11-02. Решения из раздела 7 приняты по колонке «Предложение», кроме вопроса 8: нужны данные от владельца.

Источник дизайна: артефакт «Дизайн сайта», https://claude.ai/artifact/7cYMer7dnynbZJTNpfqrPU,
файлы `project/App*.dc.html`. Актуальный экран меню: `AppSettings` («Таб · Меню: финальная
версия»). `AppSettingsV1` устарел. База сверена со staging (`foxqkomqtpbxyeqqwzpm`).

## 1. Главное

- **В меню 12 разделов.** Сейчас работают только «Финансы» и «Расходы». У «Услуг» временный
  список, «Профиль» пока заглушка, остальное нужно строить.
- **Онлайн-запись почти вся уже есть в базе:** нужно только подключить настройки к экрану.
  Веб-страница записи эти поля уже читает.
- **Больше всего новых таблиц у товаров.** Ещё новая инфраструктура нужна для шаблонов сообщений,
  пуш-уведомлений и подписок.
- **Нашли 4 проблемы вне дизайна** (раздел 5.3): номер мастера хранится не в каноническом формате,
  удаление аккаунта не доведено до конца, страница деактивированного мастера остаётся открытой,
  отпуск хранится сразу в двух местах.
- **Нет макетов больше чем для 20 состояний** (раздел 6). Их нужно нарисовать или собрать по
  существующим шаблонам приложения.

## 2. Правила реализации

| Что | Как |
| --- | --- |
| Заголовок, «назад», таб-бар, кнопки в заголовке («Готово», «+», «Закрыть», «Удалить») | Нативно, как сейчас: Liquid Glass на iOS 26. Кружки из макета не рисуем |
| Контекстные меню, системные диалоги, шторки | Нативно: `ContextMenu`, `formSheet` со `SheetChrome` |
| Всё остальное: шапка, карточки, строки, тексты, отступы, радиусы, цвета | Строго по макету, через токены темы |
| Перед каждым экраном | Читаем его макет, после сборки сравниваем со скриншотом |
| Компоненты | Сначала `shared/ui`: `GroupedCard`, `ListItem`, `SectionLabel`, `Switch`, `Chip`, `SegmentedControl`, `MonthGrid`, `TimePicker`, `DurationPicker`, `SearchField`, `Avatar`, `FormSheetContent` |
| Шторки онбординга (валюта, пояс, часы, раздел, категория, услуга) | Переиспользуем. Сейчас они в `features/onboarding` и привязаны к его черновику: выносим в общий слой, а данные передаём через пропсы |
| Миграции | Только файлы в `supabase/migrations` и `supabase db push`. После изменения схемы обновляем типы в обоих приложениях |
| Поставка | Одна фаза = один PR в `develop`, вместе с её миграцией |

### 5.2 Что лишнее

**Можно удалить.** Код использует их только в сгенерированных типах, функции базы тоже не используют:

| Колонка | Почему |
| --- | --- |
| `master_settings.calendar_first_day` | Не используется, нет в дизайне |
| `master_settings.default_calendar_view` | Наследие старого дашборда |
| `master_settings.client_reminder_whatsapp_enabled` | Заменяется шаблонами |
| `master_settings.client_reminder_offsets_minutes` | Сроки в макете фиксированные |
| `master_settings.alert_awaiting_confirmation_enabled` | Нет в дизайне |
| `master_settings.alert_upcoming_appointment_enabled` | Нет в дизайне |
| `master_settings.alert_upcoming_offset_minutes` | Нет в дизайне |
| `master_profile.place_id` | Не используется |

**Удалить после фазы 4:** `master_settings.vacation_from`, `vacation_until`. Сейчас их читают веб
(`availability.ts`, API мастера, перенос) и функция `money_open_minutes`, поэтому сначала переводим
всех потребителей на блоки.

**Не удаляем, но решить, нужны ли.** Веб их читает, а редактора в макете нет: значит, мастер не
сможет их изменить.

| Колонка | Что на вебе |
| --- | --- |
| `page_theme`, `page_accent` | Тема и цвет страницы мастера, в дизайне страницы есть варианты |
| `tiktok`, `contact_email` | Контакты на странице |
| `works_at_place`, `can_travel` | Блок «О мастере» |
| `experience_years`, `show_visits_count` | Блок на странице |
| `map_url`, `zip_code` | Карта и SEO |
| `service.photo_url` | Фото услуги |

`date_format` и `time_format` оставляем: используются, а экран для них не нужен. `is_verified` ставим
вручную, это не настройка мастера.

### 5.3 Проблемы, которые нашлись по дороге

1. **Номер мастера не в каноническом формате.** На staging в `master_profile.whatsapp` лежит
   `+996 700 000 877`, хотя правило проекта: только цифры E.164. CHECK есть у `client`, но нет у
   `master_profile`. Чиним в фазе 2.
2. **Удаление аккаунта не доведено до конца.** Колонка `deactivated_at` обещает удаление через 30
   дней, но cron для этого нет. Кнопка удаления в приложении обязательна для App Store. Чиним в
   фазе 1.
3. **Страница деактивированного мастера остаётся открытой.** На вебе `deactivated_at` встречается
   только в типах, а значит, запись к такому мастеру по-прежнему доступна. Чиним в фазе 1.
4. **Отпуск живёт в двух местах:** `vacation_*` и `time_block`. Дизайн требует список, поэтому
   объединяем в фазе 4.

## 6. Экраны без макета

В коде макетов эти строки ведут на `#` или не ведут никуда:

- **Меню:** экран QR-кода.
- **Профиль:** специализация, редакторы контактов и адреса, выбор обложки, смена ссылки.
- **Услуги:** «Направления и категории», своя длительность, выбор перерыва.
- **Товары:** «Заканчиваются → Показать», порог «мало», выбор услуги, пополнение остатка.
- **Портфолио:** добавление фото, просмотр, меню при удержании, подпись.
- **Часы:** выбор «С» и «По», неполный день.
- **Онлайн-запись:** выбор всех значений («2 часа», «30 дней», «15 минут» и другие).
- **Напоминания:** режим редактирования шаблона, выбор языка, выбор времени.
- **Настройки:** выбор языка и темы, смена почты, подтверждение удаления.
- **Помощь:** «Частые вопросы», «Предложить функцию».

Предлагаю: простые выборы делать нативным меню или существующей шторкой, а вот QR, «Направления и
категории», редактор шаблона и «Частые вопросы» сначала дорисовать в артефакте. Вопрос 7.

## 9. Порядок и зависимости

```
0 Главный экран ─┬─ 1 Настройки, Помощь ─── 10 Пуши
                 ├─ 2 Профиль ───────────── 7 Портфолио
                 ├─ 3 Услуги ─┬──────────── 5 Онлайн-запись
                 │            └──────────── 9 Товары
                 ├─ 4 Часы и выходные
                 ├─ 6 Способы оплаты
                 └─ 8 Напоминания
Все фазы ────────── 11 Чистка базы
```

Фазы 1–4 дают рабочее меню для мастера и закрывают требования App Store. Строки меню появляются
по мере готовности разделов.

## 10. Новые зависимости

| Пакет | Зачем | Нужна новая сборка |
| --- | --- | --- |
| `expo-image-picker` | Аватар, обложка, портфолио | Да |
| `react-native-qrcode-svg` | QR-код | Нет, `react-native-svg` уже есть |
| Drag-and-drop | Порядок услуг и фото: выбрать на фазе 3, reanimated и gesture-handler уже есть | Зависит от пакета |
| `expo-notifications` | Пуши | Да |

Версии ставим через `npx expo install`, перед использованием сверяемся с документацией Expo SDK 57.
